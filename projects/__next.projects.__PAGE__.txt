## Overview

A proof-of-concept demonstrating how to run a gRPC service behind an Envoy proxy that translates HTTP/JSON requests to gRPC — enabling REST clients to communicate with gRPC backends without any client-side gRPC library.

Built during my Flipkart internship while working on REST POJO to proto3 IDL conversion tooling. Distributed at Flipkart scale, service mesh patterns like this are critical — this POC was my first deep dive into them.

## Architecture

```
REST Client → Envoy (HTTP/JSON to gRPC transcoding) → Java gRPC Service
```

Envoy is configured with `grpc-http1.1-bridge` and `grpc-json-transcoder` filters. The proto descriptor is compiled and passed to Envoy at startup so it knows how to map REST endpoints to RPC methods.

## Key Learnings

- **Proto-first design matters.** The `.proto` file is the contract. Changes cascade to both Envoy config and the Java service.
- **Envoy's static config is verbose for local dev** but the xDS API investment pays off at scale.
- **gRPC status codes are not HTTP status codes.** Envoy handles mapping but you need to understand it for debugging.
- **Proto descriptor files** must be precompiled and baked into Envoy config — automate this in CI.
